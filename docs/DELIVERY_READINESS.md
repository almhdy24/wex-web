## 3. أبرز المشاكل التي تم حلها جذرياً (Resolved Root Causes)
1. **انهيار صفحة تفاصيل المنتج (404 Error):**
   - *السبب:* مخالفة قواعد خطافات رياكت (React Rules of Hooks) بوجود `useMemo` و `useRef` بعد جملة شرطية (`early return`).
   - *الحل:* إعادة ترتيب كافة الخطافات في أعلى المكون دون أي شروط مسبقة.
2. **عدم مزامنة إيقاف الطلبات (`orders_enabled`):**
   - *السبب:* عدم إرجاع الحقل في رد `GET /api/v1/shop`، مع معالجة غير دقيقة للقيم الرقمية `"0"` في الواجهة الأمامية.
   - *الحل:* تضمين الحقل في المتحكم `SettingsController::shop()`، وضبط دالة `normalizeShopInfo` للتعامل الصارم مع كافة الصيغ المنطقية، وتعطيل أزرار السلة والطلب فور إيقاف الطلبات.
3. **فقدان اسم منطقة التوصيل في صفحة الدفع:**
   - *السبب:* كان المتحكم يعيد `state_name_ar` فقط بينما الواجهة تتوقع `zone_name` أو `name`.
   - *الحل:* إثراء مخرجات `ShippingZoneController` بإرجاع `name` و `zone_name` و `fee_sdg`.
4. **تسجيل الدخول في نافذة الدفع (AuthSheet):**
   - *السبب:* كان الضغط على زر Google يغير الحالة تلقائياً إلى البريد الإلكتروني عند فشل GIS.
   - *الحل:* منع التبديل التلقائي، والإبقاء على القائمة مع توفير زر "رجوع" صريح في واجهة البريد.
5. **تجاوز زر "اختيار من المعرض" في شاشات 360px:**
   - *السبب:* تقسيم شبكي ثنائي بعرض ثابت غير متجاوب.
   - *الحل:* جعل أزرار الالتقاط والاختيار عمودية كاملة العرض على الشاشات $\le$ 440px مع ارتفاع 48px لتسهيل اللمس.
6. **قص رقم الطلب `#WEX-...` على الشاشات الضيقة 320px:**
   - *السبب:* عدم وجود `flex-wrap` و `overflow-wrap` في ترويسة تفاصيل الطلب.
   - *الحل:* تطبيق `overflow-wrap: anywhere; flex-wrap: wrap; font-size: 16px` على الشاشات الصغيرة.
7. **محاذاة حقول الأرقام والهاتف في النماذج العربية:**
   - *السبب:* تطبيق `dir="ltr"` مع `text-align: start` جعل الأرقام تبدأ من أقصى اليسار.
   - *الحل:* تطبيق `text-align: right` مع `dir="ltr"` لتبدأ الأرقام من بداية الحقل المنطقية لليمين بترتيب أرقام لاتيني صحيح.
8. **بطاقات خيارات الاستلام في صفحة الدفع:**
   - *الحل:* جعل بطاقتي "الاستلام من المحل" و"التوصيل" متساويتين تماماً في الارتفاع عبر Flexbox، وإضافة أيقونة تأكيد دائرية، واستبدال "حسب المنطقة" بسعر التوصيل الفعلي فور تحديد المنطقة.

## 4. أوامر النشر للإنتاج (Production Deployment Runbook)

### أ. الواجهة الخلفية (Backend - `wex-api`):
```bash
cd ~/projects/wex-api
git checkout stabilize && git pull origin stabilize
composer install --no-dev --optimize-autoloader
php spark migrate --all
# في حال الترقية من بيئة جديدة:
# php spark db:seed AdminSeeder
```

### ب. الواجهة الأمامية (Frontend - `wex-web`):
```bash
cd ~/projects/wex-web
git checkout stabilize && git pull origin stabilize
npm ci
npm run check:all
VITE_API_BASE_URL=/api/v1 npm run build
```

## 5. قائمة الفحص السريع على الهاتف (5-Minute Phone Smoke Checklist)
عند فتح الموقع على هاتف حقيقي (عرض 360px):
1. **المتجر:** فتح المتجر، التأكد من ظهور شريط الإعلانات، المنتجات، وأيقونات الأزرار في سطر أفقي واحد.
2. **تفاصيل المنتج:** الضغط على لابتوب، التأكد من فتح الصفحة بنجاح دون أي 404، تقليب صور المعرض، والضغط على "أضف إلى السلة".
3. **السلة والدفع:** فتح السلة، الضغط على "متابعة"، التأكد من تساوي بطاقتي "الاستلام من المحل" و"التوصيل" وظهور الأيقونة الدائرية.
4. **مناطق التوصيل:** اختيار منطقة توصيل (مثال: الخرطوم)، التأكد من ظهور اسم المنطقة ورسومها وتحديث السعر الإجمالي فوراً.
5. **رقم الهاتف:** إدخال رقم هاتف سوداني (`0912345678`) والتأكد من محاذاته جهة اليمين.
6. **تأكيد الطلب وإشعار التحويل:** تأكيد الطلب، التأكد من ظهور رقم الطلب `#WEX-...` بالكامل دون قص، وظهور أزرار "التقاط صورة" و"اختيار من المعرض" بكامل العرض بدون أي شريط تمرير أفقي.
