# هندسة النظام المعمارية (Architecture Documentation)

وثيقة معمارية شاملة لتطبيق الويب وتطبيق الويب التقدمي (PWA) لمتجر **ويكس تكنولوجي (Wex Technology)** في أم درمان، السودان.

---

## 1. نظرة عامة على النظام (System Overview)

تم بناء الواجهة الأمامية كمشروع مستقل ومنفصل تماماً داخل `~/projects/wex-web` باستخدام **React 19** ومُحزّم **Vite 8** مع دعم معايير **PWA**. يتكامل التطبيق بسلاسة مع الواجهة الخلفية المبنية بـ CodeIgniter 4 في `~/projects/wex-api` عبر واجهة RESTful API قياسية تعمل محلياً على:

```
VITE_API_BASE_URL=http://localhost:8081/api/v1
```

### المبادئ المعمارية الجوهرية
1. **الواجهة الخلفية هي المصدر الوحيد للحقيقة (Single Source of Truth):**
   - لا يتم تكرار منطق التسعير، أو حساب أسعار الصرف، أو التحقق من صحة الطلبات محلياً في جافاسكريبت.
   - الأسعار الأساسية للمنتجات مخزنة بالدرهم الإماراتي (`price_aed`)، ويتم احتساب القيمة بالجنيه السوداني (`total_sdg`) بالخادم وفق سعر الصرف النشط.
2. **عمارة واجهات أحادية الصفحة متقدمة (PWA SPA):**
   - تنقل سلس وفوري للعملاء وطاقم الإدارة.
   - كاش آمن وتدريجي دون تخزين أي بيانات حساسة أو خاصة.
3. **تصميم عربي أولاً (Arabic-First RTL):**
   - ضبط كامل لاتجاه الصفحة (`dir="rtl"`) مع خط `Tajawal` ومحاذاة رقمية دقيقة تدعم الأرقام والمصطلحات التقنية اللاتينية دون تشوه.
4. **أمان الرموز وجلسات التوثيق (JWT & Refresh Token Rotation):**
   - الرمز المميز للوصول (`accessToken`) يُحفظ في الذاكرة الحية (In-Memory).
   - رمز التجديد (`refreshToken`) يُحفظ في مساحة التخزين المؤقتة للجلسة (`sessionStorage`).
   - تجديد موحد (Single-Flight Token Refresh) يمنع التكرار وسباق الطلبات عند انتهاء صلاحية الرمز.

## 3. طبقة الشبكة والاتصال (API Client Layer)

تم بناء عميل HTTP المركزي في `src/api/client.js` باستخدام `fetch` الأصلي لتجنب حزم الأطر الثقيلة، مع توفير المزايا التالية:

```
[مكون واجهة المستخدم / React Component]
                 │
                 ▼
          [src/api/client.js]
                 │
  ┌──────────────┴──────────────┐
  │ 1. إضافة ترويسة التوثيق     │ (Authorization: Bearer <token>)
  │ 2. إضافة ترويسة JSON        │ (Content-Type: application/json)
  │ 3. منع الكتابة مع FormData  │ (Multipart boundary auto-set)
  └──────────────┬──────────────┘
                 ▼
       [إرسال طلب HTTP لـ API]
                 │
  ┌──────────────┴──────────────┐
  │ الاستجابة:                  │
  │ • رمز 200/201: فك المغلف     │ (unpack data & meta)
  │ • رمز 401: تجديد الرمز      │ (refreshAccessToken once)
  │ • رمز خطأ آخر: استخراج رسالة │ (Arabic API error extraction)
  └─────────────────────────────┘
```

### تجديد الرمز الموحد (Single-Flight Refresh Deduplication)
عندما تنتهي صلاحية رمز الوصول، وتطلق الصفحة طلبات متوازية (مثل جلب بيانات المستخدم والإشعارات وسلة الشراء)، يقوم العميل باعتراض أول خطأ `401` وإطلاق وعد تجديد وحيد (`refreshPromise`)، وتنتظر باقي الطلبات نفس الوعد بدلاً من إرسال طلبات تجديد متعددة تؤدي إلى إبطال الجلسة على الخادم.

## 4. نظام الصلاحيات وحراسة المسارات (Routing & Role-Based Access Control)

تعتمد حماية المسارات في `src/app/router.jsx` على المكون `RouteGuard.jsx`:

1. **المسارات العامة (Public Routes):**
   - متاحة للجميع بدون تسجيل دخول (`/`, `/products`, `/products/:slug`, `/cart`, `/offline`, `/404`).
2. **مسارات الضيوف (Guest Routes):**
   - متاحة فقط لغير المسجلين (`/login`, `/auth/verify`). يُعاد توجيه المسجلين تلقائياً إلى `/account`.
3. **مسارات العملاء المسجلين (Protected Routes):**
   - تتطلب جلسة صالحة (`/checkout`, `/orders`, `/orders/:orderNumber`, `/account`, `/notifications`).
4. **مسارات طاقم العمل والإدارة (Staff & Admin Routes):**
   - متاحة للمستخدمين الذين يحملون دور `staff` أو `admin` (`/admin`, `/admin/orders`, `/admin/payments`).
5. **مسارات المدير فقط (Admin-Only Routes):**
   - مقتصرة تماماً على دور `admin` (`/admin/products`, `/admin/rates`, `/admin/settings`, `/admin/shipping-zones`, `/admin/users`, `/admin/audit-logs`).
   - تمنع الواجهة المدير من تعديل صلاحيات حسابه بنفسه أو تعطيله لمنع قفل النظام عرضياً.

## 5. حالة التطبيق (State Management)

تجنب المشروع استخدام Redux نظراً لبساطة وكفاءة Context API المدمج في React 19:

- **`AuthContext`:** إدارة جلسة المستخدم، استعادة الدخول، وحالة الحساب.
- **`CartContext`:** إدارة عناصر السلة، حساب الكميات مع وضع حد أقصى للطلب (10 قطع)، والتزامن التلقائي مع `localStorage`.
- **`ToastContext`:** إظهار التنبيهات اللحظية الملونة للنجاح أو الفشل.

## 6. استراتيجية التخزين المؤقت وتطبيق الويب التقدمي (PWA Strategy)

تم ضبط مكون `vite-plugin-pwa` باستراتيجيات محكمة في `vite.config.js`:

- **عزل أمني صارم (Zero Private Cache):** يُمنع منعاً باتاً تخزين أي استجابات تخص المصادقة، الطلبات، تفاصيل الدفع، أو لوحة التحكم الإدارية.
- **تحديث أولي للبيانات العامة (NetworkFirst):** تُحفظ معلومات المتجر وقوائم الفئات والماركات العامة لتعمل بدون إنترنت وتتحدث فور توفر الشبكة.
- **تخزين صور الأجهزة (StaleWhileRevalidate):** تُحفظ صور الأجهزة في المتصفح لمدة 7 أيام لتسريع التصفح وتوفير استهلاك باقات الإنترنت في السودان.
- **كاشف الاتصال بالإنترنت (`PwaPrompt.jsx`):** مراقبة أحداث `online` و `offline` وتنبيه العميل بشريط أحمر أنيق عند انقطاع الشبكة.
- **شريط تثبيت التطبيق:** الاستماع لحدث `beforeinstallprompt` وتمكين العميل من تثبيت التطبيق كأيقونة مستقلة على هاتفه الذكي.
