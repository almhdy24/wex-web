# استراتيجية ودليل الاختبارات (Testing Documentation)

دليل شامل لاختبار واجهة **ويكس تكنولوجي (Wex Technology)**، واستراتيجية الاختبارات الآلية واليدوية.

---

## 1. فلسفة الاختبار (Testing Philosophy)

تم تصميم حزمة الاختبارات بالاعتماد على **Vitest**، وهو إطار اختبار فائق السرعة متوافق بالكامل مع بيئة Vite ويعمل بخفة تامة داخل بيئة **Termux** على أجهزة أندرويد ذات الموارد المحدودة (4GB RAM).

المبادئ المتبعة:
1. **اختبار عقود الاتصال (Contract Verification):** التحقق من دقة معالجة مغلفات API، واستخراج رسائل الخطأ العربية، والتأكد من إرسال الترويسات والحمولات المطلوبة.
2. **اختبار قواعد الأعمال المحلية:** التأكد من حسابات العملة (ج.س و د.إ)، وتثبيت الأسعار، وقواعد سلة الشراء (حد المخزون، والحد الأقصى لـ 10 قطع).
3. **سلامة حراس الصلاحيات (Role Guards):** التأكد من عزل مسارات الإدارة عن العملاء، ومنع المدير من تغيير صلاحيات حسابه بنفسه.

---

## 2. مجموعات الاختبار الآلية (Test Suites)

يحتوي مجلد `src/__tests__/` على 9 ملفات اختبار تغطي 39 اختباراً مؤتمتاً بنسبة نجاح 100%:

| ملف الاختبار | الهدف والتغطية |
|---|---|
| `api-client.test.js` | فك مغلف JSON، معالجة أخطاء 401 وإعادة المحاولة، استخراج رسائل الخطأ، وإدارة رمز التوثيق |
| `formatters.test.js` | تنسيق مبالغ الجنيه السوداني والدرهم، تحويل التواريخ العربية، وشارات حالات المخزون والطلبات |
| `price-formatting.test.js` | التحقق من الأرقام الغربية (0-9)، عدم استخدام أرقام هندية، دقة الفواصل، وأوصاف الحالة الفنية |
| `countdown.test.js` | دقة حساب الوقت المتبقي بالساعات والدقائق، وتنسيق hh:mm:ss الجدولي، وتنبيه أقل من 30 دقيقة |
| `receipt-compression.test.js` | خوارزمية تصغير أبعاد الإيصالات (max 1600px)، الحفاظ على نسبة العرض للارتفاع، وضغط JPEG |
| `orders.test.js` | التحقق من حالات الطلبات، مراجعة إشعارات الدفع، واحتساب مهلة قفل السعر (4 ساعات) |
| `cart.test.js` | إضافة المنتجات، تقييد الكميات وفق المخزون المتاح والحد الأقصى 10، وتحديث وحذف العناصر |
| `admin.test.js` | بناء استعلامات المنتجات، تحديث أسعار الصرف، تعديل أدوار وحالات المستخدمين، وفلترة سجل العمليات |
| `smoke.test.js` | فحص تكامل النظام واستيراد جميع صفحات الإدارة والمتجر بنجاح دون أخطاء تبعيات |

## 3. تشغيل الاختبارات الآلية (Running Tests)

لتشغيل الاختبارات في بيئة التطوير:

```bash
cd ~/projects/wex-web

# تشغيل جميع الاختبارات مرة واحدة (Single Run)
npm run test

# تشغيل الاختبارات في وضع المراقبة (Watch Mode)
node node_modules/vitest/vitest.mjs

# تشغيل ملف اختبار محدد
node node_modules/vitest/vitest.mjs run src/__tests__/cart.test.js
```

جميع الاختبارات مصممة لتعمل بدون الاعتماد على متصفح حقيقي عبر بيئة Node الخفيفة مع محاكاة للتخزين المحلي (`localStorage` / `sessionStorage`).

## 4. قائمة التحقق للاختبار اليدوي (Manual Verification Checklist)

### أ. تجربة العميل (Customer Journey):
- [ ] تصفح الصفحة الرئيسية واستعراض الأجهزة المميزة وشريحة سعر الصرف النبضي.
- [ ] تصفية الأجهزة في صفحة الكتالوج بالبحث ونوع الجهاز والفئة والماركة ونطاق السعر.
- [ ] فتح صفحة تفاصيل لابتوب والتحقق من جدول المواصفات الفنية ونص الضمان والملحقات المقترحة.
- [ ] إضافة الجهاز للسلة وملاحظة تحديث العداد في الهيدر، مع تجربة زيادة الكمية للتأكد من عدم تجاوز المخزون.
- [ ] تسجيل الدخول بالبريد الإلكتروني وتجربة إدخال رمز التحقق المكون من 6 أرقام مع مؤقت العد التنازلي (60 ثانية).
- [ ] إنشاء طلب واختيار استلام بالمحل أو توصيل لولاية محددة.
- [ ] متابعة شريط تثبيت السعر (4 ساعات) في صفحة الطلب ونسخ رقم حساب بنكك بنقرة واحدة.
- [ ] رفع صورة إشعار بنكك والتحقق من تحول حالة الطلب فورياً إلى "مراجعة إشعار الدفع".

### ب. تجربة الإدارة (Admin Journey):
- [ ] الدخول بحساب طاقم العمل أو المدير والتحقق من بطاقات لوحة التحكم وشريط التنبيهات.
- [ ] مراجعة إشعار الدفع المرفوع (عرض الصورة، القبول، أو الرفض مع سبب).
- [ ] تغيير حالة الطلب وتسجيل بيانات مندوب التوصيل.
- [ ] تعديل سعر الصرف والتحقق من ظهور رسالة التأكيد التحذيرية.
- [ ] إضافة جهاز جديد وتحديد مواصفاته ورفع صوره وتعيين الصورة الرئيسية.
- [ ] استعراض قائمة المستخدمين والتحقق من تعطيل زر تعديل الدور على الحساب الشخصي.
- [ ] فحص سجل العمليات الإدارية (Audit Trail) للتأكد من توثيق كافة الإجراءات.
